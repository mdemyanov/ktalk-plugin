# ktalk — Claude Code plugin

Плагин для работы с записями встреч Контур.Толк: реестр обработанных записей,
анализ транскрипта и протокол встречи, оценка качества анализа, расписание,
создание и отмена встреч по вашей санкции.

Плагин — это только промты и агенты. Всё обращение к API живёт в отдельном
пакете `ktalk-cli` (ADR-012), поэтому его нужно поставить отдельно.

## Быстрый старт

### 1. Поставьте пакет `ktalk-cli`

```bash
uv tool install ktalk-cli==2.0.0
ktalk --version       # ровно ktalk-cli 2.0.0 — шаг 3 опирается на `ktalk token`
```

Плагин объявляет точную совместимую версию в `compat.json` — не порог, а пин: любое
расхождение (и ниже, и выше пина) плагин сообщает как `outdated` и печатает команду
ремонта с этой версией явно.

### 2. Поставьте плагин

Плагин доступен двумя независимыми каналами поставки (ADR-027) — один и тот же
payload, разные маркетплейсы. Внутренний GitLab остаётся источником истины;
GitHub-зеркало — одностороннее (без обратной автосинхронизации), тег появляется
там только после успешного зеркалирования релиза с внутреннего канала.

#### Внутренний GitLab — источник истины

```
/plugin marketplace add <внутренний GitLab-адрес — см. `CLAUDE.md`, раздел «Справочные пути»>
/plugin install ktalk@ktalk-plugins
```

Обновление уже установленной копии — **обе** команды, в этом порядке, плюс перезапуск:

```
claude plugin marketplace update ktalk-plugins   # обновляет локальный кэш маркетплейса
claude plugin update ktalk@ktalk-plugins         # переводит УЖЕ УСТАНОВЛЕННУЮ копию на новую версию
```

Затем перезапустите сессию — платформа сообщает «Restart to apply changes». Первой
команды одной недостаточно: она обновляет только локальный кэш маркетплейса, не
установленную копию плагина — установленная версия останется прежней без единого
сигнала об этом, пока не выполнена вторая команда.

#### Публичное GitHub-зеркало

Одностороннее зеркало того же payload, имя маркетплейса другое (`ktalk-plugins-mirror`,
не `ktalk-plugins`) — так канал различим по имени, а не только по адресу:

```
/plugin marketplace add https://github.com/mdemyanov/ktalk-plugin.git
/plugin install ktalk@ktalk-plugins-mirror
```

Обновление — та же пара команд, что и для внутреннего канала, с именем
`ktalk-plugins-mirror`:

```
claude plugin marketplace update ktalk-plugins-mirror
claude plugin update ktalk@ktalk-plugins-mirror
```

Если версия, которую вы ищете, только что вышла на внутреннем канале, а на
GitHub-зеркале её ещё нет — это штатное окно зеркалирования (ADR-027 Д2), не
дефект: тег на зеркале появляется только при успешном `push`, поэтому список
тегов зеркала никогда не «обгоняет» реально смирролленное и не подделывает
версию, которой ещё нет.

Плагин не может включить фоновое обновление за вас — платформа не даёт издателю такого
ключа (`autoUpdate` — свойство записи маркетплейса на стороне потребителя, `claude plugin
marketplace add` не принимает флага для него). Обновление — ваше действие, эти две
команды — полный путь до него.

### 3. Положите токен

На вкладке, где вы залогинены в Толке, откройте DevTools
(`F12`, на Mac `Cmd+Option+I`) → **Console** и выполните:

```js
copy(JSON.parse(localStorage.session).data.token)
```

Токен — в буфере обмена. Положите его в файл одной командой:

```bash
pbpaste | ktalk token set -          # macOS
xclip -o | ktalk token set -         # Linux (X11)
```

Команда сама создаёт `~/.config/ktalk-mcp/token` с правами `0600` и никогда не
печатает значение. Переменные окружения задавать не нужно — файл подхватывает CLI.

Проверка:

```bash
ktalk token status    # есть ли файл и корректны ли права
ktalk auth-status     # жива ли авторизация — реальный запрос
```

Токен браузерной сессии живёт недолго. Как только запросы начнут отдавать ошибку
авторизации — повторите те же два шага, `ktalk token set -` перезапишет файл.

Если работать нужно постоянно, вместо токена сессии выпустите персональный
API-ключ в админке Толка и задайте `KTALK_PERSONAL_API_KEY` — подробности в
README пакета `ktalk-cli`.

### 4. Укажите адрес пространства

Адрес вашего пространства Толка задаётся переменной окружения `KTALK_BASE_URL`
в окружении оболочки, где работает `ktalk` (плагин не объявляет MCP-поверхность и не
несёт собственного `.mcp.json` — CLI единственный путь к контуру, ADR-022).
Значение — адрес, по которому вы открываете Толк в браузере.

## Что умеет

| Навык / команда | Что делает |
|---|---|
| `/ktalk-registry` | Реестр записей: синхронизация, просмотр, запуск обработки |
| `ktalk-eval` | Оценка качества разбора встречи |
| `ktalk-meetings` | Расписание, создание и отмена встреч, поиск участников |
| агент `ktalk-processor` | Анализ транскрипта и протокол встречи |
| агент `ktalk-evaluator` | Проверка готового протокола |

Запись в контур (создание и отмена встреч) всегда идёт через предпросмотр и ваше
явное подтверждение — одним шагом плагин её не делает.

## Настройка проекта: `.ktalk.toml`

Куда складывать протоколы и где искать профили участников — плагин не угадывает.
Положите в корень проекта файл `.ktalk.toml` (пути в примере — плейсхолдеры):

```toml
[registry]
db_path = "PATH/TO/TRANSCRIPTS_ARCHIVE/.registry.db"

[directories]
people = "PATH/TO/PEOPLE_PROFILES"
projects_active = "PATH/TO/ACTIVE_PROJECTS"

[routing]
committee = "PATH/TO/MEETINGS/committees/{id}/{date}.md"
standup = "PATH/TO/MEETINGS/standups/{date}.md"
transcript_archive = "PATH/TO/TRANSCRIPTS_ARCHIVE/{YYYY}/{date}_{type}_{title}.md"
eval_report = "PATH/TO/TRANSCRIPTS_ARCHIVE/eval/reports/{date}_{title}.md"

[integrations]
qmd = false
```

Все секции опциональны: если ключа нет, шаг честно скажет «маршрут не объявлен»
и не станет придумывать путь. **Секретов в `.ktalk.toml` быть не должно** — токен
живёт в своём файле, ключ и базовый URL в окружении.

Проверить, что конфигурация читается:

```bash
ktalk config show --json
```

## Где лежат данные

- Реестр и сырые транскрипты — в `~/.local/share/ktalk` (данные пакета, не
  проекта). `registry.db_path` в `.ktalk.toml` перебивает этот дефолт.
- Протоколы, зеркало реестра и профили участников — в вашем проекте.

Перенести уже существующий реестр в централизованное хранилище можно только
явной командой, сам плагин файл не двигает:

```bash
ktalk migrate-to-central-store PATH/TO/EXISTING/.registry.db
```

## Если что-то не работает

- **Плагин говорит, что пакет не найден или устарел.** Точная совместимая версия
  объявлена в `compat.json` (пин, не порог — расхождение в обе стороны считается
  несовместимым). Плагин может поставить пакет сам, но только по явной санкции:

  ```bash
  bash <путь к плагину>/scripts/ktalk-onboard.sh check            # состояние пакета
  bash <путь к плагину>/scripts/ktalk-onboard.sh grant install    # выдать санкцию
  bash <путь к плагину>/scripts/ktalk-onboard.sh install          # поставить
  ```

  Санкция хранится в `~/.config/ktalk/onboarding.toml` и действует на всю машину;
  обновление требует отдельной `grant update`. После `install` повторите `check`.

- **Плагин ведёт себя не так, как ожидается.** Проверьте, нет ли в проекте старых
  копий в `.claude/agents/`, `.claude/skills/`, `.claude/commands/` — они молча
  перекрывают плагин. Удалите их отдельным коммитом.

- **Опциональная интеграция с `qmd`** (сопоставление участников с профилями)
  включается ключом `[integrations] qmd = true` и только если `qmd` доступен в
  сессии. Недоступен — шаг не падает, а помечает результат как недоступный.
