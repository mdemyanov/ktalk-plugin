# AT-design: переезд требований плагина, пять capability (QA-001)

**ADR:** [ADR-023](../00-project/adr/ADR-023-plugin-requirements-relocation.md)
**Архитектура:** [2026-08-31-plugin-requirements-relocation.md](2026-08-31-plugin-requirements-relocation.md)

Тест-дизайн эпика `ktalk-plugin-56l` со стороны дерева плагина: наблюдаемые исходы переезда
четырёх требований из дерева пакета и появления пяти новых capability. Полный список
`#### Scenario:` недоступен на этом шаге — все пять `openspec/specs/*/spec.md` пишет задача
после SA-002 («Contract with QA-author» companion-статьи); ниже — тест-дизайн наблюдаемых
исходов ЭТОГО эпика (переезд, регистрация пары, отсутствие дубля с `cli-only-boundary`), не
AC переехавших требований по существу — тот тест-дизайн придёт своей задачей QA-author, когда
каждое требование обзаведётся собственной спекой (layout decision companion-статьи: «каталог-
спутник — будущая задача QA-author, когда придёт её очередь; SA и DEV-001 каталог не
создают»). Здесь каталоги-спутники `<slug>/` для четырёх переселенцев сознательно НЕ заводятся
— тот же пункт контракта.

Стаб: [scripts/test-plugin-requirements-relocation.sh](../../scripts/test-plugin-requirements-relocation.sh)
(`bash scripts/test-plugin-requirements-relocation.sh`).

## Boundary cases

- `2026-08-18-meetings-prompt-surface.md` — единственный файл с ДВУМЯ capability в одной
  строке (`meetings-prompt-surface-reads`, `meeting-write-sanction-workflow`) — стаб сравнивает
  множество slug'ов, не форму записи (одна строка через запятую vs две строки — обе валидны).
- Дата в новом имени файла — дата первого коммита ИСХОДНИКА в дереве пакета
  (`git log --diff-filter=A --follow`), не дата переезда: `2026-08-18-*`/`2026-08-19-*`
  предшествуют дате этого ADR (`2026-08-31`) — граничное условие именования, не опечатка.

## Error cases (два обязательных класса)

**Malformed/mistyped input** (искажённый, не отсутствующий, идентификатор — здесь его пишет
Dev, целевой «пользователь» механизма пары, не оператор Толка):
- REL-3/4/5, исход C: Dev называет slug неверной формы или не входящий в migration map
  (опечатка при переносе) — стаб ловит несовпадением МНОЖЕСТВА slug'ов с ожидаемым, не только
  фактом «путь похож на спеку».
- REL-3/4/5, исход D: slug правильной формы, но каталог спеки ещё не создан (несинхронный
  порядок «сначала Capability, потом спека» — прямое нарушение шага 1 брифа Dev, «Дождаться
  пяти спек... следующая задача после SA-002») — стаб ловит явным `-f`.

**Masked failure** (тихое принятие/дубль вместо наблюдаемой ошибки):
- REL-7: ничто в C15/C16 не помешает `meetings-prompt-surface-reads` завести СВОЙ сценарий «нет
  MCP» рядом с уже существующим в `cli-only-boundary` — оба валидны синтаксически, дубль
  контракта тихий (ADR-023 Д3 явно называет этот риск в «Alternatives Considered»).
- REL-8: спека онбординга может дословно унаследовать текст AC источника
  (`ktalk-plugin-onboarding.md:77,146-155`), который уже разошёлся с фактическим поведением
  `ktalk-onboard.sh` (пин `==%s`, не порог) — никакой гейт не сверяет текст спеки с текстом
  реализации автоматически; расхождение всплыло бы только при следующем ручном ревью, если
  REL-8 его не поймает раньше.
- REL-2 сам по себе — пример масштаба риска: реестр `.nauta-ids.yaml` тихо разошёлся с
  корпусом (ADR-023 добавил ADR-файл, никто не поднял `highwater`) — `check.sh --fast` этого
  не видит вовсе (`id-check.sh` только в `--full`), то есть без REL-2 расхождение оставалось бы
  невидимым до следующего `--full`, которого прецедент issue #5 (упомянутый в брифе) уже
  показал спустя семь коммитов.

## Не покрывается (out of scope этого стаба)

- Каталоги-спутники `<slug>/_index.md` + `at-design.md` для четырёх переселенцев — контракт
  companion-статьи «Layout decision» явно называет это будущей задачей QA-author, ПОСЛЕ того
  как DEV-001 создаст верхнеуровневый файл и появится собственная спека требования; заводить
  их сейчас означало бы создавать пару без предмета (спеки ещё нет) — тот же прецедент issue
  #5, что и у пустого `openspec/specs/`.
- Механизм `check_capability_link` в общем виде — тестирует сьют донора
  (`scripts/test-validate-content.sh`), не этот стаб (тот же принцип, что зафиксирован
  companion-спекой ADR-021 в дереве пакета).
- AC-полнота пяти будущих спек по существу FR/NFR четырёх исходных требований — предмет задачи
  «написать 5 спек» и её собственного QA-цикла.
