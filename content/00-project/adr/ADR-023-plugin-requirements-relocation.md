# ADR-023: Требования плагина переезжают из дерева пакета; пять capability на плагинной стороне

**Status:** Proposed
**Date:** 2026-08-31
**Capabilities:** `meetings-prompt-surface-reads`, `meeting-write-sanction-workflow`,
`plugin-onboarding-sanctioned-install`, `meeting-analysis-quality-calibration`,
`prompt-defect-channel` (пять `openspec/specs/<имя>/spec.md`, файлы заводит задача,
следующая за этим ADR — не он сам).

## Context

BA-001 эпика `ktalk-plugin-56l` развела семь требований (3117 строк), физически лежащих в
дереве пакета `ktalk-mcp`, по предмету, а не по имени файла: четыре описывают плагин вопреки
расположению — `ktalk-plugin-meetings.md:19-21` называет плагин прямо («репозиторий
`ktalk-plugin`, отдельный от этого»), `ktalk-prompt-defect-channel.md:32-33` описывает навык
`ktalk-eval` и трекер репозитория плагина вопреки отсутствию слова «plugin» в имени. Три
остаются предметом пакета, включая `ktalk-plugin.md` — единственный файл, чьё имя вводит в
заблуждение в обратную сторону (`:69` — «Код пакета (CLI и MCP-сервер)…»). Разведение самого
пакетного дерева (openspec-каркас, `.nauta-ids.yaml`) — SA-001, соседняя задача того же эпика,
не эта.

BA прямо оставила SA нерешёнными три пересечения с уже принятой capability `cli-only-boundary`
(ADR-022) и не решала их сама.

## Decision

### Д1. Четыре файла переезжают; путь-источник не удаляется — становится указателем

Переезд переносит содержание, не путь. `ktalk-plugin-meetings.md`, `ktalk-plugin-onboarding.md`,
`ktalk-plugin-analysis-calibration.md`, `ktalk-prompt-defect-channel.md` уступают текст четырём
датированным файлам этого дерева без избыточного здесь префикса `ktalk-plugin-`/`ktalk-prompt-`
(имена, migration map — companion-статья), но путь-источник в дереве пакета остаётся: файл типа
«Прочее», статус Approved, текст «требование переехало» с адресом нового файла и причиной.

Основание — факт, не предпочтение, установленный удалением и откатом, а не чтением: удаление
четырёх оригиналов в дереве пакета и прогон `check.sh --fast` там дали 34 битые ссылки в 22
документах (пять ADR, `roadmap.md`, четыре companion-спеки, три security-review, отчёты QA/A-B,
три заметки Dev), после чего удаление откатили. Все ссылки исторические — решение принималось
*против* этого требования, удаление источника превратило бы их в «решено против того, чего нет».

Цена указателя: постоянный (не временный) файл-редирект на стороне пакета, который SA/Dev этого
дерева не ведут — один предмет, две записи на диске, но без дублирования текста (указатель несёт
только адрес). Цена отклонённых альтернатив выше: разлинковать 34 упоминания в 22 закрытых
документах значит редактировать принятые ADR и закрытые отчёты ради факта, знать который они не
обязаны; не переезжать вовсе воспроизводит сам дрейф предмет/место, ради разбора которого заведён
этот ADR. Приём указателя — тот же, каким пакет `ktalk-mcp` уступает имя `ktalk-cli` (решение
владельца, вне мандата этого ADR).

### Д2. `plugin-onboarding-sanctioned-install` не сливается с `cli-only-boundary`

Пересечение (FR-26/FR-31 против сценариев «Installed version differs from the pin» / «remedy
command names the exact version») **не сливается**: `cli-only-boundary` остаётся единственным
владельцем контракта «что значит совместимая версия» (точный пин, симметричная
несовместимость, команда ремонта с версией — уже Accepted-де-факто поведением ADR-022/Д2/Д3).
`plugin-onboarding-sanctioned-install` владеет процессом обнаружения и санкционированной
установки (когда чинить, кто спрашивает, как хранится санкция — уже решено ADR-014, дерево
пакета) и лишь ССЫЛАЕТСЯ на компат-контракт, не переопределяет его.

Цена: спека онбординга не самодостаточна по вопросу «что такое несовместимость» — читатель
обязан открыть `cli-only-boundary/spec.md`. Обратная цена слияния — больше: `cli-only-boundary`
перестала бы быть границей и понесла бы пять FR онбординга (диалог, TTY-барьер, идемпотентность,
сетевые повторы), которые уже архитектурно закрыты ADR-014 в дереве пакета — слияние дублировало
бы чужое решение, а не расширяло своё.

Основание не гипотетическое: AC текста BA (`ktalk-plugin-onboarding.md:77` — «`uv tool install
ktalk-mcp`» без версии; `:146-155` FR-31 — язык «не ниже минимальной») уже разошёлся с фактически
поставленным поведением (`scripts/ktalk-onboard.sh` строит `remedy_cmd_text` с `==%s`-пином,
`pin_version()` явно отказывает при отсутствии точного ключа). Задача, пишущая спеку, обязана
описывать сценарии по факту реализации и по словарю `cli-only-boundary`, не транскрибировать
устаревший AC BA дословно.

### Д3. NFR-20 сливается с «no MCP interface surface» `cli-only-boundary`, обобщённо

`NFR-20` (`ktalk-plugin-meetings.md:268-277`, узкий grep MCP-имён операций встреч) — частный
случай уже принятого в `cli-only-boundary` требования «The plugin declares no MCP interface
surface». `check-plugin-composition.sh` уже сегодня несёт ОБЕ проверки раздельно: узкую
(«MCP-имя операции встреч вместо CLI», `:59-61`) и общую, декларативную (`check_no_mcp_server`,
`:85-130`, довод ADR-022 Д1). QA-дизайн `cli-only-boundary` (тест 46,
`content/30-requirements/2026-08-31-cli-only-boundary/at-design.md`) уже поймал ровно класс
дефекта, который и есть обобщение NFR-20 — устаревший промт-текст, описывающий MCP как живой
канал, хотя декларация уже снята. Решение: `meetings-prompt-surface-reads` не заводит свой
сценарий «нет упоминания MCP» — обобщённая формулировка (декларация И текст промт-слоя не
описывают MCP-путь) входит в `cli-only-boundary`, задача-автор спек расширяет её вторую
Requirement, а не создаёт дубль в новой capability.

Цена слияния: `cli-only-boundary` берёт на себя проверку промт-текста ВСЕГО плагина, не только
меню встреч — расширение уже принятой (Proposed) формулировки требования, не пересмотр (правило
supersede не применяется — тело ADR-022 не редактируется, меняется только текст будущей спеки).
Цена раздельности (отклонено): узкий список имён рискует не поймать соседний навык, добавленный
позже, — уже наблюдавшийся в этом дереве класс промаха (тест 46).

### Д4. Не ломает наблюдаемый контракт контура

В отличие от ADR-021 (языковая граница промт-слоя, меняет текст промтов) и ADR-022 (снятие
MCP-поверхности, ломает прямой вызов `mcp__ktalk__*`), это решение не меняет ни код, ни
CLI/MCP-поверхность, ни поведение навыка — только адрес и оформление документа требования.
Наблюдаемый эффект есть только у документарного контура: перенос обязан произойти одним шагом
с добавлением строки `**Capability:**` (после появления пяти спек) — иначе C15 немедленно
красит дерево плагина. В дереве пакета та же проверка молчит по независимой причине — путь-
источник несёт тип «Прочее», не «Требование» (Д1), и C15 применяется только ко второму; это не
зависит от того, готов ли в пакете openspec-каркас (SA-001, к моменту этой правки уже готов).
Порядок фиксирован в брифе Dev companion-статьи.

## Consequences

**Positive:** предмет и расположение снова совпадают для всех одиннадцати требований волны;
`cli-only-boundary` остаётся единственным источником правды о версии/MCP-декларации, дрейф
между двумя формулировками одного факта невозможен по построению.

**Negative:** спека онбординга не читается в одиночку по вопросу совместимости версии;
`cli-only-boundary` перестаёт быть только про декларацию и берёт на себя текст промт-слоя;
четыре постоянных файла-указателя остаются в дереве пакета (Д1) — предмет, живущий в двух
записях на диске вместо одной.

**Mitigations:** явная кросс-ссылка из будущей спеки онбординга на `cli-only-boundary/spec.md`;
расширение текста `cli-only-boundary` — это правка спеки (не тела ADR-022), обычный жанр
итерации контракта, не supersede; указатель называет причину и точный адрес — переход по старой
ссылке не обрывается, а объясняется.

## Alternatives Considered

- **Слить все пять capability плагина в `cli-only-boundary`.** Отклонено — см. Д2: дублирует уже
  закрытое ADR-014 архитектурное решение об онбординге.
- **Оставить NFR-20 отдельным сценарием `meetings-prompt-surface-reads`.** Отклонено Д3 —
  узкий список имён уже один раз пропустил дефект (тест 46 `cli-only-boundary`).
- **Переименовать `ktalk-mcp` в `ktalk-cli` заодно.** Отклонено эпиком на входе (genesis-заметка
  `ktalk-plugin-56l`): ждёт зелёного дерева, не входит в эту задачу.
- **Разлинковать 34 ссылки в 22 документах дерева пакета вместо указателя (Д1).** Отклонено —
  правка принятых ADR и закрытых отчётов ради факта, знать который они не обязаны; стирает
  трейл «решено против X».
- **Не переезжать вовсе, оставить содержание в дереве пакета (Д1).** Отклонено — воспроизводит
  сам дрейф предмет/место, ради разбора которого заведён этот ADR.
