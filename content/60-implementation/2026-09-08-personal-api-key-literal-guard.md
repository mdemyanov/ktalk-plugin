# Реализация: сторож на литерал `KTALK_PERSONAL_API_KEY` в промт-слое (ADR-028 Д5)

**Capability:** `openspec/specs/session-only-auth/spec.md`

Д5 ADR-028 вводит машинно-проверяемый сторож на решение Д1 (сессионный токен — единственный
поддерживаемый режим): литерал `KTALK_PERSONAL_API_KEY` не должен появляться в промт-слое как
поддерживаемый/рекомендуемый вариант. Периметр — дословно Scenario «No prompt-layer file names
the retired mode as supported»: `README.md`, `references/`, `skills/`, `agents/`, `commands/`.

## Что сделано

- `scripts/check-plugin-composition.sh`: добавлена `check_no_retired_auth_literal()` — по
  образцу `check_payload_domain()` (scoped-скан по явному списку путей), не общего `check()`
  (whole-tree): периметр отличается от «MCP-имя операции встреч» сознательно у́же дерева.
  `scripts/`, `content/`, `openspec/` вне периметра: `scripts/` легитимно диагностирует сам факт
  наличия переменной (`ktalk-onboard.sh:311`, `test-onboard.sh:229,233`), `content/`/`openspec/`
  обязаны цитировать литерал как исторический факт о коде пакета (та же ловушка, что уже поймана
  для внутреннего домена GitLab, ADR-027 Д4) — общий `check()` по всему дереву поймал бы RES-001,
  требование BA-001 и сам этот ADR.
- `scripts/test-session-only-auth.sh`: блок `GUARD-1..GUARD-6` — тест самого механизма сторожа
  (не содержания дерева, это уже покрывает `AC1-1`). Приём — изолированная копия дерева
  (`mktemp -d` + `cp -r "$ROOT"`, `.git` вычищен), тот же, что тесты 40/44a/44b
  `scripts/test-onboard.sh` для регресса `check_no_mcp_server`: инъекция литерала внутри
  периметра валит гейт и называет файл (`GUARD-2a/b`), удаление литерала возвращает гейт в
  зелёное состояние (`GUARD-3`), тот же литерал в `scripts/` и в `content/` (вне периметра)
  гейта не валит (`GUARD-4`, `GUARD-5`), а собственный литерал стаба AC-1 в
  `test-session-only-auth.sh` (это тот же файл, что исполняется) сторож не ловит вовсе —
  `scripts/` целиком вне периметра (`GUARD-6`, masked failure).

## Нетривиальное

- Разница между общим `check()` (построчный blanket-запрет по всему дереву за вычетом
  `.git`/`__pycache__`/`.beads`/`agent-memory`/себя) и `check_payload_domain()`-style scoped-
  сканом — не деталь реализации, а прямое следствие того, что периметр Д5 у́же дерева и
  включает каталоги, легитимно несущие тот же литерал. Повторное использование общего `check()`
  для этого сторожа было бы неверным по конструкции, не только по факту (упало бы на RES-001 и
  на самом ADR-028).
- Эксперимент «сторож способен покраснеть» (обязательный по брифу DEV-002) проведён дважды: один
  раз вручную на живом дереве (`git checkout` откатил правку после проверки, `git status
  --short` пуст), второй раз как постоянный регресс-тест (`GUARD-2a/b` выше) — оба находят один
  и тот же файл в сообщении гейта.
- `GUARD-3` использует `sed -i.bak '/.../d'` вместо восстановления файла из git — копия дерева
  во временном каталоге (`$GUARD_TMP`) не несёт `.git` (удалён явно, как и в паттерне
  `test-onboard.sh`), поэтому `git checkout`/`git show` там недоступны.
