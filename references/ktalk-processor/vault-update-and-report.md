# Hybrid update and final report

A reference file of `ktalk-processor.md` (core steps 6 and 7).

Every literal in the fenced blocks below is written into the host's vault or printed to the
operator — reproduce it verbatim, never translate it (ADR-021 D1).

## Automatic (no confirmation)

**Participant profiles** (only if `registry.directories.people` is declared and the directory
exists — otherwise the step is marked unavailable rather than half-performed):

- Append an entry to the `История 1-1` section (for meetings of type 1-1)
- Update or append rows in the profile's open agreements — as **two separate Edits**, not one
  merged change: first the revision of existing rows after the reconciliation (step 5.5 of
  `ktalk-processor.md`), then — as a separate Edit — the addition of new rows in the format:
  ```
  | {дата} | {договорённость} | {срок или —} | ⬜ не начато |
  ```
- Add `ktalk_id` to the profile frontmatter if it is absent
- State the source: `> Обновлено на основе встречи "{название}" ({date})`

**Projects** (only if `registry.directories.projects_active` is declared):

- Add the meeting to the project card's log: `{путь}/{id}/{id}.md`
- Update the status of an existing task if it was said explicitly that the task is finished

**The registry (through the `ktalk` CLI, without editing markdown):**

On successful processing — move the record to `done`, filling in the paths and the type:

```
ktalk mark-done {recording_id} \
  --transcript {путь по registry.routing.transcript_archive} \
  --protocol {save_location} \
  --type {meeting_type}
```

If no protocol was created (`archive_only`), omit `--protocol`.

If processing turned out to be **partial** (it could not be carried through — an incomplete
transcript, an interrupted analysis), use this instead of `mark-done`:

```
ktalk mark-partial {recording_id} \
  --transcript {путь по registry.routing.transcript_archive} \
  [--protocol {save_location}]
```

The CLI sets the status, the paths and `processed_at` atomically and updates the SQLite
registry. The markdown mirror is regenerated by the orchestrator (`ktalk export`) — the agent
does not need to touch it.

## With confirmation (show the list → wait for the user's answer)

- Create a profile for a new person (absent from the profile directory)
- Create a new project
- Close a project or change its status
- Create an architectural decision (ADR / decision record)
- Change a priority in the project configuration (where applicable)

The confirmation request format:

```
⚠️ Требует подтверждения:

1. Создать профиль: "Артём Пермяков" (ktalk:3197, упомянут в встрече)
2. Создать ADR: "Выбор Flowable для BPM движка" (обсуждали архитектурное решение)

Подтвердить все? (да/нет/выборочно: 1,2)
```

### Hard-stop report (transcript identity unresolved after the retry)

When step 2b's retry still does not confirm participants, the meeting was NOT processed — the
report does not carry the "✅ Встреча обработана" header, and nothing about the transcript,
protocol, or vault is claimed as done:

```
⛔ Обработка остановлена: recording_id {recording_id}

Личность транскрипта не подтверждена: после повтора участники, найденные в полученном
содержимом ({participants actually found}), не совпали с ожидаемыми участниками встречи
({participants из launch context}).

Ничего не сохранено и не архивировано — реестр помечен: ktalk mark-partial {recording_id}.
```
