# Contributing

## Заведение issue по дефекту промта

Issue заводится только для класса дефекта, встретившегося в таблице `Defects` трекера
качества `ktalk-eval` на 2+ разных записях. Класс, встретившийся один раз, остаётся строкой
трекера — issue не заводи.

Обязательные поля тела issue (перенос из секции «Дефекты промта» отчёта 1:1, без
переформулирования): класс (id из `skills/ktalk-eval/references/defect-classes.md`), тип
встречи, измерение рубрики, цитата транскрипта, цитата протокола, предложенное правило — по
каждому подтверждающему случаю.

Issue без пары цитат (транскрипт + протокол) хотя бы для одного случая — не заводи, дефект
остаётся строкой трекера до появления полной пары.

Перед заведением: замени в цитатах имена сотрудников на роль/обезличенный идентификатор,
удали или замени плейсхолдером названия клиентов и внутренние суммы. Прочитай собранное тело
целиком перед публикацией — репозиторий плагина читается анонимно, без авторизации — опубликованный текст видит кто угодно, откатить
опубликованный текст нельзя.

## Версия плагина и тег релиза

Версию `.claude-plugin/plugin.json` поднимает та же правка, что меняет промт-слой
(`agents/`, `skills/ktalk-registry/`, `references/ktalk-processor/`): minor — по NFR-25.
Проверяет это `check_prompt_version_sync` в `scripts/check-plugin-composition.sh`, сравнивая
версию рабочего дерева с версией в `origin/main`. Отсюда следствие: в пределах одного
неопубликованного изменения minor поднимается один раз, сколько бы раундов доработки оно ни
прошло. Периметр сторожа — источник истины о том, что считается промт-слоем; при расхождении
с этим перечислением прав скрипт.

После слияния в `main` тег создаёт платформа, не `git tag` руками:

```bash
git checkout main && git pull --ff-only
claude plugin tag --dry-run   # печатает форму тега и коммит — прочитай перед созданием
claude plugin tag             # создаёт и пушит тег
```

Команда формирует ровно ту строку, которую платформа резолвит при разрешении версионных
зависимостей — `<плагин>--v<версия>`, например `ktalk--v1.11.0` — и попутно сверяет
`plugin.json` с записью маркетплейса; отдельной проверки на это не нужно (ADR-025 Д1).
Внутри она делает `git tag -f` и `git push --force`, поэтому запускай её на коммите слияния
и только для ещё не выпущенной версии: перемещение уже опубликованного тега молча подменяет
то, что резолвится по этому имени у тех, кто его однажды разрешил.

Шесть исторических тегов формы `vX.Y.Z` (`v1.3.0`…`v1.9.0`) остались от прежней конвенции
и не переписываются — по той же причине (ADR-025 Д1).

Тег ставится всегда, даже если никто не ставит плагин по тегу: потребители по умолчанию
получают обновление с ветки через `claude plugin marketplace update ktalk-plugins`, а тег —
единственная точка, по которой видно, какому состоянию дерева соответствует объявленная
версия. Пропущенный тег обнаруживается не сразу и восстанавливается вручную по истории.
